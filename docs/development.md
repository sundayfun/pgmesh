# Development and verification

Development commands use [just](https://github.com/casey/just). Run `just`
without arguments to list all recipes. The repository installs pinned sqlc and
golangci-lint binaries under `bin/` as needed.

## Verification commands

| Command | Purpose |
| --- | --- |
| `just test` | Run all unit and example tests. |
| `just lint` | Run the pinned linter with `.golangci.yaml`. |
| `just verify-unit` | Regenerate checked-in code, then run tests, vet, and lint. |
| `just integration` | Start PostgreSQL, run integration and example smoke tests, then clean up. |
| `just verify` | Run both the non-Docker and Docker-backed verification suites. |

The checked-in generator fixtures at `tests/same_package`,
`tests/separate_package`, and `tests/command_shapes` each own a `sqlc.yaml`,
schema, queries, generated output, and basic API tests. They are generated by
sqlc v1.31.1 and compiled as part of the module tests.
Table-driven tests cover topology validation, signed and unsigned hashing,
virtual-shard ranges, annotation parsing, route conflicts, sqlc command shapes,
pgx/v5 type mappings, and generated option combinations.

For non-Docker verification, run:

```bash
just generate-tests
just --justfile examples/justfile generate
go test ./...
go test -shuffle=on -count=1 ./...
go test -race ./...
go vet ./...
just lint
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
```

## Local PostgreSQL integration

`tests/docker-compose.yaml` starts five isolated PostgreSQL 18
databases:

| Endpoint | Default port | Purpose |
| --- | ---: | --- |
| `shard0-primary` | 25432 | Primary for virtual shard 0 |
| `shard0-replica0` | 25433 | First read endpoint for shard 0 |
| `shard0-replica1` | 25434 | Second read endpoint for shard 0 |
| `shard1-primary` | 25435 | Primary and read fallback for shard 1 |
| `shard0-mirror` | 25436 | Synchronous write mirror for shard 0 |

The replica containers are intentionally independent databases, not a
streaming-replication cluster. Tests seed different marker rows into each one
so they can prove which endpoint handled a generated read. The suite checks
round-robin replica reads, primary fallback, forced-primary reads, virtual-shard
write routing, synchronous mirrors, transaction pinning, mirror suppression in
transactions, real pgx `ErrNoRows` mirror handling, nullable/network/range
scanning, separate-package generation, physical-shard scatter, grouped
list-lookup routing and result ordering, grouped `COPY FROM` routing and mirror
fan-out, and the deliberate lack of mirror fan-out for generated batch writes.

PostgreSQL-backed scenarios live directly in feature directories such as
`tests/read_replicas`, `tests/async_copy`, `tests/scatter`, and
`tests/write_mirrors`. Shared pool and assertion helpers live under
`tests/internal`; they do not contain scenarios. Add new behavior to its own
feature directory by default. `tests/transactions` keeps one explicitly named
`mixed_features_integration_test.go` scenario to prove transaction, COPY,
sharding, and mirror suppression compose correctly without turning focused
tests into end-to-end catch-alls.

Run the complete local validation with:

```bash
just verify
```

To run only the Docker-backed integration suite:

```bash
just integration
```

For debugging, control the lifecycle separately:

```bash
just integration-up
just integration-test
just examples-smoke
just integration-down
```

`just integration-test` runs every feature directory serially against the
shared local topology. To run one focused feature against an already-running
topology, use:

```bash
just integration-test-feature async_copy
```

To regenerate one generator fixture, start PostgreSQL with that fixture's
schema, run its associated integration coverage, and clean up, use:

```bash
just integration-case same_package
```

The accepted fixture names are `same_package`, `separate_package`, and
`command_shapes`. In GitHub Actions, the fixtures run as parallel matrix jobs,
each with an isolated Docker Compose topology. The `same_package` job owns the
feature-focused runtime directories because they share its generated API and
schema.

Override the default ports with:

- `PGMESH_SHARD0_PRIMARY_PORT`
- `PGMESH_SHARD0_REPLICA0_PORT`
- `PGMESH_SHARD0_REPLICA1_PORT`
- `PGMESH_SHARD1_PRIMARY_PORT`
- `PGMESH_SHARD0_MIRROR_PORT`

The tests also accept corresponding full DSN overrides by replacing `_PORT`
with `_DSN`.

## Continuous integration

Separate GitHub Actions workflows check formatting and module-file drift, build
every package, run tests with the race detector and coverage, lint, scan known
vulnerabilities, verify generated code, run the Docker-backed integration suite,
and smoke-test the examples. Failed integration and example runs upload their
Docker logs, and test runs upload their coverage profile, for seven days.
